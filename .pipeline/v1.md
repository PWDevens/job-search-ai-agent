# Job-Search AI Agent — v1

A **fully local, open-source** job-search assistant. Upload your resume, point it at jobs, and a
3-agent AI pipeline tells you **which roles to prioritize, how to strengthen your resume, and where
your career blind spots are** — grounded in authoritative labor-market data, with **no cloud APIs and
no data leaving your machine.**

Local LLMs via Ollama · ChromaDB retrieval · O*NET-grounded reasoning · MIT licensed.

---

## What it does

Give it a resume + a target role (and optionally a set of jobs), and three agents run in sequence:

| Agent | Output |
|---|---|
| **Job Matcher** | Ranks the most relevant jobs and explains *why each fits* |
| **Resume Coach** | Prioritized, gap-closing resume recommendations tied to real requirements |
| **Career Strategist** | Critical blind spots (skills/experience/ATS gaps) + a strategy to close them |

Served through a local Flask web UI (`run.py` → `http://localhost:5000`) or run headless.

## Why it's different

- **Local-first & private.** Everything runs on your hardware (Ollama + ChromaDB). No keys, no cloud, no telemetry of your resume or targets.
- **Grounded, not hallucinated.** Advice is anchored to **real job-posting requirements** and the **US O*NET** occupation database — not the model's imagination.
- **Hardware-adaptive.** Auto-detects your machine and selects a model that fits, no config required.
- **Evidence-driven.** Every major design choice was settled by a persona-based evaluation harness, not vibes (see *How it was validated*).

## Architecture

```
Resume + target role ─┐
                      ▼
   Retrieval (ChromaDB + bge embeddings + cross-encoder rerank)
                      ▼
   Full-text job postings ──► section parser ──► requirements_text
                      ▼                                │
   Job Matcher ──► Resume Coach ──► Career Strategist  │
                      ▲                                ▼
        O*NET authoritative requirements ◄── target occupation
        (AUTHORITATIVE_GAPS: grounds blind spots/recs in real,
         occupation-level requirements, not truncated postings)
```

- **Framework-free 3-agent pipeline** on Ollama with **Pydantic JSON-schema-validated** outputs (grammar-constrained — no brittle parsing).
- **Full-text sourcing.** Pulls complete job descriptions from **ATS public APIs (Greenhouse / Lever / Ashby)** — free, structured, no bot-walls — instead of truncated aggregator snippets. A deterministic section parser extracts the requirements block for grounding.
- **O*NET grounding (`AUTHORITATIVE_GAPS`).** Derives the target occupation from matched roles and injects that occupation's real, in-demand requirements, so gap analysis holds even when a posting is thin.
- **Intent-aware.** Stay-in-field vs. career-switch mode tailors each agent's framing.
- **Effort dial.** `quick / balanced / thorough / max` trades retrieval breadth + passes for speed.

## Models (hardware-tiered)

Selected automatically by `app/hardware.py`; override with `AGENT_MODEL=…`.

| Tier | Model | Notes |
|---|---|---|
| No NVIDIA GPU (CPU / iGPU / Apple) | **qwen3:4b** | Best overall *and* smallest; fast everywhere |
| NVIDIA GPU ≥ 10 GB VRAM | **gemma3:12b** | US-developed (Google), generalizes across personas |

These won a **13-model bake-off** (see below). Requires `OLLAMA_NUM_CTX≥8192`.

## How it was validated

The project is driven by a **persona evaluation harness** (14 occupations × switch/stay intent) that
scores job-match, resume-rec, and blind-spot quality against authoritative requirements. Key results
that shaped v1:

- **Full posting text beats truncated snippets by +0.41 overall (14/14 personas).** Un-truncation via ATS APIs is a real lever — the requirements section is what grounds good advice.
- **The base model is the single biggest lever (+0.76–0.79 overall).** A small reasoning model (qwen3:4b) beat much larger ones; scaling up *backfired*. Cross-cell testing caught models that looked strong on one persona set but regressed on the other.
- **O*NET authoritative grounding** lifted blind-spot quality substantially over posting-only grounding.
- Honest negatives (documented, not shipped): occupation-taxonomy injection (ESCO), best-of-N sampling, a verification pass, and occupation-pivot suggestions all landed at the noise floor.

Full iteration log: `reports/IMPROVEMENT_LOG.md`.

## Getting started

```bash
# 1. Install Ollama (https://ollama.com) and pull a model
ollama pull qwen3:4b           # or gemma3:12b on a real GPU

# 2. Python deps
pip install -r requirements.txt

# 3. Run the local web app
python run.py                  # -> http://localhost:5000
```

Ingest your own jobs (CSV/XLSX) into the local store:

```bash
python scripts/ingest_jobs.py path/to/jobs.csv --clear
# or pull full-text postings from ATS boards:
python scripts/pull_ats.py --ingest
```

Docker Compose is also provided for a one-command local stack.

## Configuration (key env vars)

| Var | Purpose |
|---|---|
| `AGENT_MODEL` | Force a specific Ollama model (skips hardware tiering) |
| `OLLAMA_NUM_CTX` | Context window (must be ≥ 8192) |
| `EFFORT` | `quick / balanced / thorough / max` |
| `AUTHORITATIVE_GAPS` | O*NET requirement grounding (default on) |
| `HARDWARE_TIER` | Force `cpu / gpu_avg / gpu_modern` |

## Limitations (honest)

- **Speed vs. quality.** Larger models (gemma3:12b) are slow on CPU/iGPU-bound laptops; the eval measures answer *quality*, not tokens/sec. The hardware tiers err toward what runs acceptably.
- **Discovery is corpus-bound.** Job retrieval is only as good as what's ingested; cross-field switch targets may not be present in a given corpus. (v2 addresses this — see `v2_specs.md`.)
- **ATS coverage is partial.** Greenhouse/Lever/Ashby cover many employers but not all; aggregator (Adzuna) snippets are truncated and their redirects are bot-walled.
- **Apple-Silicon detection.** `detect_tier` probes `nvidia-smi` only, so Macs fall to the CPU model (still the best model, fast on Metal).
